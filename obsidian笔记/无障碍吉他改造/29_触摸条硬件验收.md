## 三、踩过的三个坑（教训）

### 坑 1：脚号不能靠「树莓派标准排布」外推

第一次报的 `31/35/40/39/36/38` **全错**——其中 39 脚是 GND，OUT 插进去信号直接被拉死。
第二次从板定义 `lckfb_tspi.py` 推导 + 三处硬事实交叉验证（脚 8/10=UART3 已实测打通、脚 3/5=I2C2 实测、脚 18=GPIO3_A5=编号 101 官方确认）才定稿。

> **纪律**：给脚号前必须从板定义核，不许靠记忆外推。这是本项目第 2 次在这上面翻车（第 1 次是引脚卡把 GPIO3 印成 GPIO0）。

### 坑 2：C6 首轮不通 = 杜邦线没插到位

用「C5/C6 对调」一次定位：摸 C5 时脚 32 有反应、摸 C6 时脚 26 有反应 → **脚号对、模块好、线不断**，纯粹是那根杜邦母头没插到底。
换回原位、插紧后 C6 正常。

> **判读四象限**（值得复用）：对调后 ①两边都有 → 接触不良 ②只有脚32无 → 脚号错 ③只有脚26无 → 模块坏 ④两边都无 → 线断。

### 坑 3：TTP223 电容感应会「半触发」

首轮监测中 C1 在 3.5~5.1s 之间跳变 **6 次**（0.3~0.5s 级）。不是硬件噪声，是**手指接近但还没碰到**时的临界感应。
代码里原来的 `debounce: 0.05` **只是轮询间隔，不是去抖**——每 50ms 读一次、读到什么信什么，这种毛刺会被完整采进去，**正式演奏表现为和弦乱跳**。

## 四、代码修正：加真去抖

**改动**：`src/guitarist/trigger_source.py`

1. 新增 `_DebouncedPin` 类：**连续 N 次采样一致**才认定电平真的变了（真去抖）。
   - `feed(v)` 返回 `True`=确认变高（可发 PLAY_CHORD）/ `False`=确认变低（可发 STOP）/ `None`=无确认变化。
2. `TouchStripTrigger.__init__` 新增参数 `debounce_samples: int = 3`（`debounce` 保持轮询间隔语义，向后兼容）。
3. `_run_gpio` 改用去抖器，不再直接判沿。
4. `trigger_integration.py` 从配置读 `trigger.debounce_samples` 传入。
5. 两份 `config.yaml` 新增 `debounce_samples: 3`（默认 3 × 50ms = **150ms 确认延迟**；人手换和弦远慢于此）。

**新增测试**：`src/guitarist/_test_touch_debounce.py`（9 段 A~I，已并入 `run_tests.sh`）
- 连续 3 次高才确认 / 不足 N 次不确认 / 毛刺交替全程不触发 / N=1 退化直读 / 按下中单次毛刺不误判松手 / 长按只发一次上升沿 / N=5 第 5 次才确认 / stable 属性。

**验证**：`bash run_tests.sh` → **8/8 全绿**（原 7 个 + 新增去抖）。

| 项 | 旧记录 | 实测（2026-10-05） |
|---|---|---|
| 泰山派系统 | Android 13 出厂态、需烧 Ubuntu | **Ubuntu 22.04.5 LTS**，内核 6.1.141 aarch64，已 root，Python 3.10.12，**Blinka 已装** |
| 刷机 | 待办 | **已完成，不用刷** |

**三条操作纪律**：
1. USB 必须插**机箱后置口**（前置口供不上，`adb devices` 全空）。
2. `adb devices` 报 `model:Nexus_4 / mako` 是**伪装名**，真身看 `uname -a` → `lckfb`、`/proc/device-tree/model` → `lckfb tspi V10 Board`。
3. Git Bash 下跑 adb 必须先 `export MSYS_NO_PATHCONV=1`，否则 `/sys/...`、`/data/...` 被转成 Windows 路径。
4. 长时监测**不要**用 `adb shell python3 xxx.py` 前台跑（USB 抖动会掐断，实测 75 秒只活了 6 秒）→ 用
   `adb shell 'cd /data/local/tmp && setsid python3 -u tsw.py 100 > tsw.log 2>&1 < /dev/null &'` 后台跑再 `adb pull` 日志。
