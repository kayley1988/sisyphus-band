## 一、接线总表（当前桌面的实际接法）

| 外设 | 接哪 | 具体脚/线 |
|---|---|---|
| **OLED 0.96" SSD1306** | 泰山派 I2C2 | VCC→面包板红轨、GND→蓝轨、**SDA→脚 3**、**SCL→脚 5**，地址 `0x3C` |
| **触摸条 6×TTP223** | 泰山派 GPIO | OUT → 脚 **7 / 12 / 18 / 22 / 26 / 32**（详见 [[29_触摸条硬件验收]]） |
| 供电 | 泰山派 40PIN | 1 脚、17 脚 = 3.3V（分两路）；9 脚 = GND 共地 |
| PCA9685 | **不接泰山派**，接小智板 ESP32-S3 | SDA=GPIO2 / SCL=GPIO1 / 0x40 |

⚠️ **脚 3 的烧件风险**：40PIN 上 2 脚和 4 脚都是 **5V**，3 脚夹在中间。数错或插偏一格 = 5V 灌进 3.3V 的 SSD1306，当场烧屏并可能连带烧泰山派 I2C 引脚。**接线前必须断电**。

## 二、实机结果

### 1. 设备认到、中文字体在位

```
i2cdetect -y 2  →  3c 出现（接前基线全空）
[font] 中文字体加载成功: /usr/share/fonts/truetype/noto/NotoSansCJK-Regular.ttc
[oled] SSD1306 128x64 初始化成功 addr=0x3C
```

板上另有 `wqy-zenhei.ttc` / `DroidSansFallbackFull.ttf` / `NotoSerifCJK`——**中文不会变方块**，这正是 `hardware.init_fonts()` 找的路径。

### 2. 真菜单 15 屏全部渲染

`tools/menu_oled_demo.py demo` 轮播：主界面（含底部 her_hint 横幅）→ root 菜单 8 项逐项反白（`> ` 前缀 + 反色条，与 `oled_renderer.show_menu` 同版式）→ 演奏模式（full / her）→ 她的演奏（按和弦 + 就位提示）→ 待触发。

root 菜单即 `menu_system.py` 里那份：**她的演奏**、**演奏模式**、WiFi连接、离线歌曲列表、AI语音设置、舵机校准设置、电源管理与监控、设备信息。

### 3. 触摸 → 屏幕 联动（核心）

`tools/menu_oled_demo.py touch 150` 实测波形：

```
 17.7s  按住 C1 -> C        21.4s  按住 C2 -> G
 28.6s  按住 C3 -> Am       34.3s  按住 C4 -> F
 38.7s  按住 C5 -> Dm       42.7s  按住 C6 -> Em
（每个之后都正常记录「松手」，心跳行同步印证 C3=1 / C4=1 / C5=1）
```

屏幕同步显示：

```
┌──────────────────┐
│ 她的演奏          │
│ 按住: Am          │
│ 保持 2.4s         │
│ ████████████████ │ ← 反白横幅
│ 和弦已就位 请拨弦 │
└──────────────────┘
```

**这条验证了 her 模式的一条关键设计**：切到 her 后压弦是**无声**的（full 里压弦+拨弦同瞬、声音即反馈），所以必须补一个「和弦已就位」的视觉提示——现在它在真机上成立。参见 [[24_her模式守护层_就位提示与超时保护]]。

## 三、两个坑

### 坑 1：板上有旧版自启程序独占 GPIO

```
PID 2340 /root/guitarist_app/.../run_with_system_log.py
systemd 服务 guitar.service，从 2026-03-24 一直活着至今
```

- **症状**：脚本开 GPIO 报 `[Errno 16] Device or resource busy`——**不是线错、不是脚号错**。
- **性质**：板载是 **3 月旧版**代码，不含 10 月的两种演奏模式、去抖修正、定稿脚号。
- **解**：`systemctl stop guitar.service` → 6 路 GPIO 立刻全部可读。
- **未办**：长期应把最新 `src/guitarist` 同步到 `/root/guitarist_app/src` 再 `restart`。该服务开机自启，**重启板子它会自己起来继续占 GPIO**。

### 坑 2：窗口过期被误判成"没反应"

第一轮 90 秒窗口，日志只有「6 路就绪 → 结束」，Z 反馈"全部按了没有反应"。真因是**摸的时候脚本已经跑完了**（发消息与操作之间隔了 3 分钟以上）。

> **交互纪律**：凡「启动窗口 → 让人去操作」的长时任务，窗口要给到 **≥150 秒**，且**必须在启动完成后**再发"开始操作"的提示；先发长解释再启动 = 窗口被吃掉。已给脚本加**心跳**（每 5 秒打印 6 路原始值），无跳变时也能区分「没摸到 / 恒 1 插错脚 / 脚本死了」。

| `tools/menu_oled_demo.py` | `demo [秒]` 菜单轮播 · `touch [秒]` 触摸-屏幕联动（带心跳）· `stop` 清屏 |

脚本自己初始化 I2C+OLED+字体，**不 `import hardware`**——后者 import 时会自动 `init_buttons()` 抓 GPIO3_A1~A4（按键没接会重试后抛异常）。
