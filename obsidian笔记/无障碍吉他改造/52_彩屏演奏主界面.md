## 📐 版式（240×240）

```
┌────────────────────────────────┐
│            稻 香               │ y 0~46   歌名 32px 亮黄·居中
│──────────────────────────────│ y 45
│   [Am]      [Dm]              │ y 52~82  和弦标签带（变化点才标，
│                                │          拨弦橙/压弦青，随音浪滚）
│   ▂▃▅█▅▃▂ ▂▅█▅▂ ▃▆█▆▃          │ y 90~178 音浪柱（中线上下对称）
│  ▎                             │          x=26 白色播放头竖线
│──────────────────────────────│ y 180
│  1  2  3  4  5  6      G      │ y 186    弦号 + 当前和弦
│  [3][ ][ ][ ][2][3]   和弦    │ y 199~221 压弦符号（按=青底品位数字）
│  ▬▬▬▬▬░░░░░░░░░░░  27%        │ y 228    进度条
└────────────────────────────────┘
```

- **音浪柱双色语义**：🟠 橙 = 该拍有拨弦动作；🟢 青 = 纯压弦换拍
- **从右到左**：`x = 26 + (t_音符 − t_现在)/窗口 × (240−26)`，窗口默认 7s → 播放头左边是刚弹过的、右边是即将弹的（预告效果）
- **柱高** = 按弦数代理强度：`0.35 + 0.65×(按弦数/6)`，拨弦再 +0.15（⚠️ 不是真音频波形，是演奏动作密度）

## 🔧 实现要点（5 条）

| # | 要点 | 说明 |
|---|---|---|
| 1 | **时间轴口径与真实演奏严格一致** | `ServoController.precompute_song()` 的 `wait_ms`（70BPM 基准）→ 真实毫秒 = `wait_ms × 70/BPM`（稻香 604 音符 × 367ms ≈ 222s ✓ 实测吻合） |
| 2 | **和弦名反查** | 6 弦品位 tuple → `data/chord_definitions.csv`（51 个标准指法）反查，同名不重复标、只标变化点。**内联解析 10 行，不依赖 guide_engine**（板上没有） |
| 3 | **碰撞避让** | 密集段和弦标签会重叠黏成"A Em"→ 相邻标签水平重叠时跳过后面的 |
| 4 | **numpy 加速刷屏** | `_flush_p` 逐像素 Python 循环 → numpy 向量化 `((r>>3)<<11)\|((g>>2)<<5)\|(b>>5)` → `astype(">u2")` 大端直出。板端 numpy 2.2.6，无则回退旧循环 |
| 5 | **粗校准防脱同步** | 本地时钟推算连续进度 + ESP32 整数百分比偏差 >5% 时纠偏 t0 |

**字体缓存**：`LCDRenderer._ttf(size)` 带字典缓存（truetype 每次 new 很慢）。

## ⚠️ 诚实说明已知边界

- **和弦匹配不到就空**：非标准指法（如稻香前奏 `[0,1,0,2,3,3]`）不在 51 个形状表里 → 只画音浪不标名；表可随时补行
- **音浪是动作密度不是音量**：没有音频文件，用"按弦数+拨弦"做强度代理，有起伏但非真实波形
- **刷新约 5~6 FPS**：SPI 12MHz 发一帧 115KB ≈ 77ms 是物理下限，滚动是"跳动"不是丝滑——但预告效果足够
- `guitar.service` 调试期间保持 stop（抢 UART），演奏完要 `systemctl start guitar` 恢复
