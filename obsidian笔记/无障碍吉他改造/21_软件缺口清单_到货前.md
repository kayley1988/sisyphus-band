## 一、本次已修的硬伤（每条都有证据）

### ① `hardware.py` 用了 `Optional` 却没导入 → **整个程序起不来** 🔴

- **事实**：`hardware.py:161` 写 `def init_touch_strip(pins: Optional[list] = None)`，但文件里没有 `from typing import Optional`。Python 在**定义函数时**就要解析注解 → `NameError` → 模块导入失败。
- **后果**：`main.py:33` 第一句就是 `from hardware import i2c, oled, ...` → **main.py 直接崩在启动第 3 行**，连菜单都进不去。
- **为什么之前没发现**：两个 PC 测试只走了 `trigger_source / trigger_integration`，**从没 import 过 hardware.py**（那文件依赖 Blinka，PC 上装不了）——典型的"测试全绿但功能是坏的"。
- **修**：加 `from typing import Optional, List`。
- **证据**：用泰山派真实引脚白名单做严格桩，`import hardware` → **通过**。

### ② 触摸条 6 个引脚里 **3 个不存在**、1 个撞串口 🔴

对照泰山派板定义 `package/gpio/adafruit_blinka/board/lckfb_tspi/lckfb_tspi.py`（共暴露 29 个脚名）：

| 我们原配（占位） | 真相 |
|---|---|
| GPIO3_C0 | 存在，**但它是 UART3_RX —— 就是通 ESP32 的那条串口**，不能占 |
| GPIO3_C1 | ❌ **板定义里没有** → AttributeError |
| GPIO3_C2 | ✅ 存在 |
| GPIO3_C3 | ✅ 存在 |
| GPIO3_D0 | ❌ **没有** |
| GPIO3_D1 | ❌ **没有** |

- **后果**：`getattr(board, "GPIO3_C1")` 直接抛 AttributeError → `init_touch_strip` 五次重试全失败 → **返回 None，触摸条彻底报废**，她的触发权没了，整套无障碍设计归零。
- **已占用清单**（避让依据）：I2C2=`GPIO0_B5/B6`(OLED)、UART3=`GPIO3_B7/GPIO3_C0`(→ESP32)、按键=`GPIO3_A1..A4`(回退 `B0..B3`)、I2C3=`GPIO3_B5/B6`、SPI=`GPIO4_C2/C3/C5/C6`。
- **修**（改成板定义里真实存在、且全项目无引用的 6 个脚）：

```
GPIO1_A4 / GPIO3_C4 / GPIO3_A5 / GPIO3_A6 / GPIO3_A7 / GPIO3_C5
（备选：GPIO3_C2、GPIO0_B7）
```

- **证据**：反证测试——用**旧引脚**跑 `init_touch_strip` 返回 `None`（触摸条报废）；用**新引脚**返回 6 路 GPIO 就绪。
- **已同步**：`hardware.py` 默认值 + `config/config.yaml` + `config/config.example.yaml`。

### ③ 自动演奏调用了一个**不存在的方法** 🔴

- **事实**：`trigger_source.PerformanceController.consume()` 里 `PLAY_SONG` 分支调 `self.player.play_song(path)`。而 `ESP32Player` 的全部方法里**没有 `play_song`**——真实入口是 `send_csv(path)` + `play()`。
- **后果**：自动演奏（调试/彩蛋路径）走到这里必抛 AttributeError，被 try/except 吞掉 → **静默失败，什么都不发生，日志里只有一行 error**。
- **修**：改成鸭子类型兜底——有 `play_song` 就用，没有就 `send_csv() + play()`。
- **证据**：模拟调用链返回 `[('send_csv','/tmp/song.csv'), ('play',)]` ✅。

- **✅ 上半机（RK3566 泰山派）的验证可继承**（2026-10-01 修正，原表述有误）：
  证据 — README §191「目标平台：RK3566 泰山派 — Ubuntu 20.04.6 LTS (aarch64)」；§5「硬件演奏控制（RK3566嵌入式端）」；板卡定义 `package/gpio/.../lckfb_tspi` 直接 `import ...rockchip.rk3566`；作者家目录 `/home/lckfb/`。

- **❌ 唯一真正不能继承的是「下位机控制板外设」**：
  拨云的 ESP32 控制板 = PCA9685 + **电流采样运放** + **EEPROM 认板**；我们 = 小智 ESP32-S3 + **裸 PCA9685 蓝板**。
  → 差异只有三处：① 电流采样读数（改用外接 **MAX471 模块**补齐 → 电流法已复活）② EEPROM 认板（已用 `FORCE_BOARD_ID=3` 绕过）③ 引脚映射（已用 `XIAOZHI_PROFILE` 重指派）。
  MCU 同为 ESP32-S3，**帧协议、固件主体、上位机通信全链路不变**。
- 但"可继承"指的是**原始设计在原板通过**，不等于**在我们的接线组合上一定通过**：真正没被验证过的是"小智板 + 裸 PCA9685 + 我们的引脚映射"这一**特定组合**，到货后必须实测（见第三节 B 类）。
- 我们这层的验证方式：**假串口 / 假 FrameLayer / 严格引脚桩**——能证明"逻辑和字节对"，**不能证明"硬件能跑"**。

## 七、电流采样 + 菜单兜底入口（2026-10-01 第二轮落地，Z 拍板「两个都要做」）

> Z 原话：「电流采样需要加，然后它的演奏手动入口也需要做。」

### 7.1 电流采样：改用外接 MAX471 模块（A 类缺口 #5 关闭）

**选型**：优维客 MAX471 电压电流传感器模块（¥16.3）—— **±3A / AT 脚 1V/A / 高边自取电 / 零电流 0V**。
零电流 0V 这点关键：它和《拨云》的换算公式 `I = V / (shunt × gain)` 天然兼容；换成带偏置的霍尔（ACS712 等）就得改固件做偏置补偿。

**接线**（详见 [[17_小智板接线与烧录SOP]] 第五节）：
`5V PSU+ → 模块 RS+ → RS- → PCA9685 V+`（全部舵机电流流过模块）；`AT → 1kΩ → AIN0(GPIO4)`。
⚠️ 接 **AT**（电流）不是 **VT**（电压）。

**标度改动（固件 + 上位机双改）**：

| 位置 | 原值 | 新值 |
|---|---|---|
| `esp32_platformio/.../board_profiles.cpp` `XIAOZHI_PROFILE.scale` | `0.005Ω × 92.0` = 0.46 V/A（V6.0 控制板运放） | **`1.0 × 1.0` = 1.0 V/A** |
| `src/guitarist/power_monitor.py` | **没有 board_id=3 分支**（会误用 V5.1 的 82.25 增益！） | 新增 `_BOARD_PROFILE[3]`，并让 shunt 也随板型切换 |

顺带修掉一个真隐患：上位机 `_BOARD_PROFILE` 只有 1/2（V5.1/V6.0），**我们板子 board_id=3 落不进任何分支** → `set_board_id(3)` 返回 False、换算沿用 V5.1 增益，**电流显示从根上就是错的**。已补 3 号分支。

**到货标定（一次）**：加载已知电流 I → 读 AIN0 电压 V ⇒ 把乘积改成 V/I。

**诚实边界**（已写进代码注释 + SOP）：±3A 量程 < 和弦总线正常演奏峰值 **3.12A**（固件实测值）⇒
**标定段（单舵机 <1.5A）准；全程演奏读数饱和；过流保护(阈值 5.0A/4.0A)形同虚设**，改靠 5V20A 电源自身限流 + 保险丝兜底。

### 8.2 ⚠️ 但这不是"少做一个动作"，是换了一种乐器——三件事必须处理

| # | 问题 | 为什么全包模式下不存在 | 怎么办 | 状态 |
|---|---|---|---|---|
| 1 | **压弦是无声音的** | 全包模式：她点一下 → 机器压弦+拨弦，**立刻有声**，天然反馈 | 她弹模式：点完只有"机器压住了"、**一点声音都没有**。必须给明确提示：OLED / LED 显示「**和弦已就位，请拨弦**」（`her_performance_ui` 已可承载） | ✅ 已实现（就位提示 + 可选提示音） |
| 2 | **保持时间变长 → 舵机发热** 🔴 | 全包模式：压完紧接着拨弦，保持只有**一瞬** | 她弹模式：要**压住直到她自己拨完**（数秒）→ 12 路 MG996R 持续接近堵转 → 发热 / 掉扭矩 / 耗电飙升。**这可能就是 M1 电磁铁翻身的理由**（吸合保持、功耗低、几乎不发热），退路：限流降力、机械自锁 | ✅ 已实现（保持超时自动松弦 + 预警） |
| 3 | **"什么时候拨"没有节拍锚点** | 机器拨弦自带时点，她只需听 | 她得**自己数拍**。触摸条按下反馈要快（`debounce=0.05` 够用），但"压到位"这个确认必须能被她感知（见 #1） | ✅ 已实现（预备拍倒计 4·3·2·1） |

> 🔴 #2 是真正的工程风险，不是体验问题：**全包模式可以蒙混过关，她弹模式不行。** 拨弦调试时务必顺带测「压住不放 5 秒」的舵机温升与电流。

### 8.4 ✅ 三件事已落地：`her_mode_guard.py`（2026-10-01 第三轮）

八节 8.2 列出的三条不是"体验优化"，是 her 模式**上线前必须闭合的工程缺口**——它们在 full 模式下全都不存在，所以《拨云》原作里一行都没有。已单独实现为守护层：
