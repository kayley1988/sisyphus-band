## 🎯 为什么要做

[[30_OLED菜单与触摸联动验收]] 里挖出的隐患：板上有 `guitar.service` **开机自启**，跑的是板载旧代码（实测为 10/2–10/3 版），它活着就**独占 GPIO/OLED/I2C**，我们的调试脚本一律报 `Device or resource busy`。

同步上板的意义：
1. 板载逻辑与 PC 开发版一致（含 10/5 的触摸条去抖修正、定稿脚号）；
2. 服务自启从"隐患"变成"我们要的行为"——开机即主界面；
3. 后续调试只需 `stop/start` 切换，不用再担心版本分叉。

```bash

# 1. 停服务
"$ADB" shell systemctl stop guitar.service

# 2. 备份板载旧版
"$ADB" shell 'BK=/root/guitarist_app_backup_20261005; mkdir -p $BK; \
  cp -a /root/guitarist_app/src/guitarist $BK/guitarist; \

# 4. 推配置（⚠️ 只覆盖两个 yaml，保留 deepseek_api.key / servo_config.csv）

# 5. 编译校验
"$ADB" shell 'cd /root/guitarist_app/src && python3 -m compileall -q guitarist'

# 6. 启服务 + 看日志
"$ADB" shell systemctl start guitar.service
```

### 自检里那 3 项 INCONCLUSIVE 是什么（都是没接的硬件，不是故障）

| 项 | 原因 |
|---|---|
| `esp32_protocol` | `CTRL_MODE_SWITCH (NORMAL) ACK 超时` → 小智板没上电/PCA9685 未接 |
| `adc_channels` | MAX471 电流采样模块还没接 |
| `auth_configured` | 未配 `WEB_API_KEY`（仅本机可访问，无碍） |

另有 `servo_probe` SKIPPED（需 service mode）。**`esp32_frame_link` PASS = 串口链路本身是通的**。

## ⚠️ 踩到的坑

1. **adb shell 里嵌 `python3 -c` 带 `|` 或多层引号会被板上 bash 解析炸**（`syntax error near unexpected token ')'`）。→ 长脚本一律写成 `.py` 文件 push 上去跑（故有 `board_config_check.py`）。
2. **推配置别整目录覆盖**——`config/` 里有 `deepseek_api.key`，只推两个 yaml 即可。
3. **先 `rm -rf` 再 push**，否则本地删掉的文件会在板上残留成孤儿。
