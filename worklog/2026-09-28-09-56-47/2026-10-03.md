## OCR 多进程部署：sticky session（任务 141–144）

用户指令：「加 sticky session」。承接 2026-10-02 的 OCR 后台任务化（内存态 `globalThis` 单例，
多进程部署需粘性分发）。

### 实现
- **`server.js`（新建，零依赖）**：master `net.createServer({ pauseOnConnect:true })` 收 TCP 连接，
  按**客户端 IP** djb2 哈希（`::ffff:` 归一化）把整个 socket `w.send(msg, connection)` 给 worker；
  worker `httpServer.emit('connection', socket)` 让 Node 内建 HTTP 解析器接管 —— 业务零感知。
  `WEB_CONCURRENCY=N`（默认 1 = 等价 `next start`）；`/api/__worker` 探针返回命中 pid（不进 Next）；
  `server.on('upgrade')` 转发 `app.getUpgradeHandler()`（dev HMR websocket）；SIGINT/SIGTERM 优雅退出；
  worker 崩溃自动拉起；send 失败降级到任一活 worker。
- **ecosystem.config.js**：改为 fork 模式跑 `server.js`（`instances:1` 固定，内部 WEB_CONCURRENCY 才管多进程；
  **PM2 cluster × 内部 cluster = 两层，前层就把任务打散**）。env_production `WEB_CONCURRENCY:'2'`。
- **nginx.conf**：⚠️ 修真 bug —— 通用 `proxy_read_timeout 60s` 会掐断 OCR SSE（MinerU 跑 20 分钟）。
  新增 `/api/ocr/` 专用 location（`proxy_buffering off` + `proxy_cache off` + read/send 1800s）；
  多实例时 upstream 加 `ip_hash`（注释示例，开源版自带）。
- **package.json**：`start:cluster`、`verify:sticky`。

## 英文资料被门禁一刀切 → 已修（夜）

- **现象**：Z 上传英文 txt（A Blot In The 'Scutcheon，71.6KB）→ 红字「中文仅占 0.0%，疑似乱码或非中文资料」。
  文件**解析是成功的**，是 `content-gate.ts` 硬门槛 `LOW_CJK`（cjkRatio<0.15 → REJECT）把「有效英文」和「乱码」一刀切。
- **修法**：`TextStats` 加 `latinChars/latinRatio`；阈值加 `minLatinRatio:0.3`。
  cjkRatio 低时分流：拉丁占比 ≥0.3 且乱码率 ≤5% → 新 code **`FOREIGN_TEXT`（WARN）**——
  硬门槛 WARN 自动升成 gate `REVIEW` → 走现有 UI 确认流（确认后 gateConfirmed 重跑，生成结果仍是中文剧本）；
  真乱码（拉丁也低）照旧 `LOW_CJK` REJECT。pipeline/UI 零改动（REVIEW 流现成）。
- **回归**：content-gate **62/0**（新增 3.5 段 11 项：英文→WARN+FOREIGN_TEXT、乱码→仍 REJECT）、
  gate-loop **69/0**（需 `BASE_URL=http://127.0.0.1:3010`，默认 3000 是环境坑）、tsc 0。
- 进化指纹 `computeContentSignature` 只取固定字段，加 latinRatio 不影响旧指纹。
