### 诊断：改造前那道门是假的（代码事实）

| 缺陷 | 证据 |
|---|---|
| 唯一检查是字符数 | `generate-from-pdf/route.ts` 只判 `text.length < 500` |
| "判断"只是一次分类咨询 | `case-paradigms.ts:337 selectParadigmByAI` |
| **模型无法说"不适合"** | 输出 schema 只有 `{paradigmId, reason}`，11 范式必选一个 |

| 失败静默兜底 | 无 key/超时/JSON 坏 → `fallback()` 硬编码经典推理，用户不知情 |
| 生成失败也继续 | `script-pipeline.ts:268` 只 `console.warn` 降级，流程仍报"成功" |

后果：菜谱、财报、乱码扫描页、重复页，只要 ≥500 字全部放行 → 被硬套成凶杀案。

### 实现：三层门禁 + 产出质检

新增 `src/lib/content-gate.ts`（~600 行）：

**Layer 1 硬门槛（零 token）**——5 项客观测量：
- 文本长度 <500 字 → REJECT
- 中文占比 <15% → REJECT（乱码/非中文语料）
- 乱码字符（控制符+U+FFFD+私用区）>5% → REJECT
- **5-gram 重复窗口占比** >45% → REJECT，>30% → WARN
- 目录/版权页/纯页码行占比 >60% → REJECT，>35% → WARN

> 为何用 5-gram 而非整段哈希：中文自然短语重复有 5%~15% 基线；整段哈希只能抓完全复制页，5-gram 能抓"交替重复"（扫描卷页、复制粘贴拼接）。

**Layer 2 适配度评估**——与 `selectParadigmByAI` 的四个本质区别：
1. 输出有 `suitable` + `confidence` → **模型可以说不适合**
2. 上下文更厚：摘要 800 字 + 章节串 + 知识点串 + 人物数 + **首/中/尾三段原文抽样**（不再只看开头 400 字被序言误导）
3. 显式给出判定维度（可推理因果链？可角色化主体？可隐藏真相？自成体系？）
4. 失败**不静默兜底** → `evaluated:false` + `unevaluatedReason`，交上层明确告知

**Layer 3 分流**：硬门槛 REJECT（跳过 LLM 省 token）/ `suitable=false` / `confidence<0.4` → REJECT；`0.4~0.7` / 未评估 / 硬门槛 WARN → REVIEW；否则 PASS。
REVIEW 抛 `GateReviewRequiredError`（携带完整 gate 结果），UI 展示理由 + 建议范式，用户点"仍用 X 生成" → 带 `gateConfirmed:true` 重跑，第二次不再拦。

**Layer 4 产出质检**——生成成功 ≠ 产出合格：推理链闭环（`fromClue` 能否追溯到 `clueChain`，复用 `resolveFromClue` 口径）、线索数、角色数、**证据归属覆盖**（角色≥3 但无人持有材料 → "拿证才能追问"玩法会失效）、物证、知识卡片。不阻断，但标记 `lowQuality` 让 UI 显示"⚠️ 存在质量提示"并逐条列出。

**用户原话**：「可以的，就按照你的想法去实现。」（此前用 AskUserQuestion 追问过两个缺口，用户四项全选：反馈回路、低质量自动重试、生成记录可观测、"三项都做"）

### 三条闭环

**一、`GenerationRecord` 只追加事件流**（Prisma，3 索引）
- 主键用自增 `cuid` 而非复合主键 —— 这是**事件流**，没有"更新同一条"的语义
- `userId` **可空**：游客也能生成，也上报（`userId=null`），否则拿不到完整拦截率
- 埋点 **fire-and-forget**：不 await、异常静默、`keepalive: true` —— 埋点失败绝不影响生成（红线）
- 关键字段 `overridden`（用户推翻门禁）—— 这是"真进化"的核心信号，改造前没有任何地方记录它

**二、反馈回路判据 = `overridden × qualityOk` 的<u>组合</u>**
| 组合 | 含义 | 建议 |
|---|---|---|
| 被拦下 → 用户强行生成 → 产出**合格** | 阈值**拦错了**（过严） | ⬇️ 放宽 |
| 被放行 → 产出**不合格** | 阈值**过松** | ⬆️ 收紧 |

**设计取舍（最重要）：不做自动改阈值。** `gate-tuning.ts` 只出建议报告（含样本量+可读证据），由人 review 后手改 `GATE_THRESHOLDS`。理由：阈值一改影响所有用户；样本量小时统计不可靠（`MIN_SAMPLE_SIZE=20` 才给建议）⇒ 自动调参 = 让噪声决定产品行为。

**三、低质量自动重试：位置选在「创意生成后立刻」**
- 结构缺陷（推理链断裂/线索过少/无证据归属）**全来自创意输出**，物证与 TTS 都是派生的
- 这里重跑只花 ~20s；等全流程跑完再检就要连封面（~10s）+TTS 一起重跑，成本高得没人愿意用
- 两条防护：**只有确实更好才采用**（防劣化）、**上限 1 次**
- 阻断判据：`WEAK_TRACEABILITY`（可追溯率<60%）/ `FEW_CLUES`（<3）/ `NO_REASONING`（<2）；`NO_HOLDER` 只提示不阻断

**四、管理侧**：`/admin/data` 拆 Tabs，新增「🚦 生成记录与门禁调参」（误伤率 overrideRate、覆盖成功率 overrideSuccessRate、调参建议卡、记录明细，游客标 `(游客)`）

## 进化经验库：把「无状态生成」改成「有记忆生成」

**用户原话**：「进化」（对上一轮我提问「①让系统自己越跑越好 ②它是某个『进化支持系统』的内容生产工具」的二选一回答）

### 关键取舍：能自动学什么、不能自动改什么

上一轮我明确反对「自动改 `GATE_THRESHOLDS`」，这个判断**没变**。但「进化」不能因此停摆。本轮把界线划清：

| 可以自动学（本轮实现） | 不能自动改（维持上轮决定） |
|---|---|
| 「这类内容 → 用哪个范式」的经验 | 全局阈值 `GATE_THRESHOLDS` |
| 「模型反复犯哪个错」的避坑清单 | 硬门槛的任何一条判定规则 |

**学「内容 → 策略的映射」是安全的**（错了只影响同类内容，可回滚）；
**改「安全线的位置」是危险的**（一改影响所有输入）。

### 两类经验

**① `paradigm_hint`（判断进化）**——内容指纹 → 验证过的范式 + 权重
- 指纹五维分桶：长度 / 中文占比 / 5-gram 重复率 / 目录占比 / 平均行长 → `L2C2R0B0G1`
- **刻意不用标题**：「第三章」「第一节」会让同一本书每章指纹都不同，经验永远命不中
- 命中且 `samples≥3`、`weight≥0.66` → `runContentGate` 走「经验采纳通道」，**跳过本次 LLM 适配度评估**

**② `pitfall`（生成进化）**——缺陷 code → 累计次数
- ≥3 次激活 → 生成前注入修复指令（**事前规避**，比事后重试便宜：重试要重跑一次完整创意生成 ~20s）
- **60 天未复现自动失效**（防陈年结论长期支配行为）
- 映射表必须覆盖 `checkCreativeQuality` / `checkOutputQuality` 报出的**全部 7 个 code**（回归有断言，漏一个就漏一条规避）

### 三条安全边界（写进代码注释的硬约束）

1. **经验只影响范式选择与 prompt 追加，绝不放松硬门槛** —— 回归有专门断言：硬门槛 REJECT + 样本 999 权重 1.0 的经验 → **仍 REJECT**；乱码文本同样不能被放行
2. **只有门禁 `PASS` 的生成才回写范式经验** —— 被拦下后 override 强行生成的内容不进经验池，否则「被判不适合的内容」会因某次结构合格的产出被学成「该放行」，把偶发误伤升级成系统性漏洞
3. **样本/权重不足一律不采纳**；避坑有 TTL

### 存储取舍

`EvolutionMemory` 表**刻意不带 `userId`** —— 进化是系统级能力，全体用户的反馈共同把系统喂聪明；按用户隔离 = 每个用户都从零开始（那是「记忆」不是「进化」）。只存统计特征与结论，**不存任何原文片段**。

`@@unique([kind, sig])`；权重由**服务端**算（Laplace `(ok+1)/(ok+bad+2)`），不信前端。

## 扫描件与几百页文档：PDF 解析链路的三个坑（提交 `393b313`）

**用户原话**：「如果明天又不需要，那就不在里面了。但是我说的有的是那种扫描版的，
文件给他几百页的，可能是需要 MinerU 呢。」

即：**别把 MinerU 这条正路给绕过了**。逐条核实分流链路，发现对大体积扫描件有三个真问题。

### ① 分流判据是绝对字符数 → 几百页扫描件被误判为电子版（最严重）

`pdf-parser.ts` 原来是 `text.length > 100`。**扫描件常带页码/页眉的文字层**：
300 页 × 10 字 = 3000 字 > 100 ⇒ 判为「电子版」⇒ **MinerU 根本不会被调用**，
用户拿到一份只有页码的空壳。

改为**每页字符密度**：`hasRealTextLayer(textLength, pageCount)`，
`MIN_CHARS_PER_PAGE = 50`（正文一页通常 500~1500 字）。抽成导出函数是为了可直测边界
—— 不必真造几百页的 PDF 固件。**注意别把判据改回绝对阈值。**

### ② MinerU 超时写死 5 分钟 → 几百页必然超时

一页 OCR 约 1~3 秒，300 页需 5~15 分钟。且 `execFile` 超时只抛 `killed`，
**看不出是超时还是跑不动**。改为 `getMineruTimeoutMs()`（默认 20 分钟，`MINERU_TIMEOUT_MS` 覆盖）
+ 识别 `killed/SIGTERM` 给可操作提示。路由 `maxDuration` 一并对齐（600/120 → 1800）。

### ③ OCR 缓存键掺了随机临时路径 → 缓存永不命中

`getCacheKey` 原来掺 `filePath + mtimeMs`，而 `/api/ocr/pdf` 落盘的临时文件名是
**随机 UUID** ⇒ 键每次不同 ⇒ **缓存永不命中**：重试永远从头跑 15 分钟，
`.ocr_cache` 只增不减。改为 `computeOcrCacheKey()` 只按**文件内容**（大文件采样首尾各 1MB）。

### 顺带修的两个门进来的同类问题

- `parsePDFBuffer` 写死 `forceOcr = true` ⇒ `/api/scripts/generate-from-pdf` 的电子版也被逼走 OCR
- 同一路由 `pdfResult.pages`（是数组）当页数用，打印/返回的都是整个数组 → 改 `pageCount`

### ⚠️ 核实中发现一个更大的问题，**未修**

`book-extractor.ts` 的 `extractBookElements()`：`maxTextLength = 30000`，**纯截断**
`text.slice(0, 30000)`。**500 页文档 OCR 出 40 万字，只送 7.5% 进模型**
—— 「OCR 辛苦跑 15 分钟，模型只看得到前 30~50 页」。
两条修法（首中尾采样 / 分段提取合并）都属**产品行为变更**而非缺陷修复，留待用户确认，未动手。

### 验证

`verify-zero-config.mjs` **26 → 41 项**（新增 B4~B8：密度判据 7 个边界、超时可配、
缓存键同内容同键、`parsePDFBuffer` 不强制 OCR、大文档标记），
外加**真实固件实证**：`电子版 → engine=pdf-parse`、**`扫描件 → engine=mineru`（没被降级绕过）**。

全量回归：`tsc` 0 错误、content-gate 51/51、gate-loop 69/69、cloud-mirror 24/24、
admin-data 36/36、evolution 80/80、user-isolation 16/16。

## 三、长文本采样：终结「几百页文档只读前 3 万字」（提交 `6af8ba3`）

### 方案（用户选 A：均匀分块采样）
