# 2026-10-11（晚）开机"一直启动中"根治：异步引导 + 关热点监控

## 现象
开机后彩屏长时间停在「启动中，请稍候...」，用户以为开机卡死。

## 定位（journalctl _PID= / gdb 线程栈 / strace -p / /proc/*/task/*/wchan）
- 启动序列本身**是跑完的**（23:16:37 已打印「系统就绪 / OLED 主界面已显示」），
  但随后主线程**同步**执行 `onboarding.start_onboarding()`：无 WiFi 环境下
  `force_start_hotspot()` 每次 nmcli 建热点要 **25s 超时 + 射频重置重试**，
  连续多次 → 主线程被卡 **2 分 32 秒**（23:16:17 启动 → 23:18:49 才轮到 Web/主循环），
  这段全程屏幕就定格在 `_start_boot_wait()` 的「启动中」帧。
- **根因土壤**：`config/.first_boot_done` 不存在 → `is_first_boot()` **每次开机都返回 True**。
- 旁证：gdb 全线程栈显示吃 CPU 的是 sherpa-onnx 推理线程（非渲染争抢）；
  主线程曾停在 ioctl(119=spidev3.0)/poll；strace 显示主线程在反复调 nmcli
  （读 `GENERAL.STATE:30 (disconnected)`）。

## 修复
1. 运行时（可逆）：`date > /root/guitarist_app/config/.first_boot_done`
2. 代码 `main.py`（已上板，md5 `d31e439dfb1f28ec7df3c966dfa00d45`，备份 `main.py.bak_1011_boot`）：
   - onboarding 块整体搬进后台 daemon 线程 `_onboarding_worker`（先置位
     `onboarding_active`）→ 日志「首次使用引导已转入后台（不阻塞开机）」
   - `hotspot_monitor.start()` 注释关闭（**能力保留**，Web 仍可手动配网）→
     日志「热点自动监控已禁用（插电本地使用；需要配网时由 Web 手动触发）」

## 验证（每次都是 systemctl restart 实测，启动→进主循环耗时）
| 场景 | 耗时 |
|---|---|
| 旧代码 + 首次引导（删标记模拟） | **2 分 32 秒** |
| 新代码 + 非首次启动 | **19 秒** |
| 新代码 + 删标记模拟首次 | **19 秒** |

## 附带发现（已确认，未改代码）
- 开机头 3 秒会刷 6 条 `无法打开音频流: Invalid sample rate [-9997]` ——
  是 `mic-path-main.sh` 配置音频通路的**竞态**，随后自动重试成功。
  **麦克风实际完全正常**：`麦克风诊断 — 平均幅度 5692~5731 / 峰值 31575`、`唤醒监听流已启动`。
  建议后续优化：首次失败降级 WARNING + 短退避重试（待用户拍板）。
- 语音链路确认可用：RK809 codec（card0 / pcmC0D0c）+ sherpa-onnx 唤醒（唤醒词「小爱同学」）
  + Vosk 中文 ASR（`vosk-model-small-cn-0.22`）。

  否则 `/root/...` 被转义成本地路径导致 push 失败。
- 板端跑渲染类脚本会打"GPIO 初始化失败 Device or resource busy"——是 import 链条的副作用，
  服务占着 GPIO，属预期，不影响渲染验证。
- 开机图/选歌屏暂未主题化（只动了演奏主界面 + 兜底进度条），要不要跟随模式待 Z 拍板。

## ESP32「发亮光」诊断结论（非烧毁）
- 用户报"ESP32 突然发很亮的光"，照片定位 = GOOUUU 板上 **IO48 板载 WS2812 RGB 灯**（针35，丝印 G48 旁）

### PCA9685 电源域答疑（Z 问：V+ 排针要不要接）
