### ⑥ 「无原调不能真移调」的根因（用户问，我给到函数行 + 修法）
- **实测**（C 大调音阶全链路）：有原调 C→D：移调量 **+2**、音高 62…74、`<fifths>` 2 → **真的搬了**；**无原调**→D：移调量 **0**、音高原样、`<fifths>` 2 → **听感与原曲完全相同，只换了记号**。
- 根因：`nearest_transpose()` 的 `if source is None ... return 0`。**这个逻辑本身没错**（源调未知时移调在数学上就是未定义的），`analysis_key()` 只读 `metadata["key"]`。
- **真正的问题是同一个控件有了两种语义**：有原调 = 「把音乐搬到目标调」；无原调 = 「把谱重新记成目标调」。且后者在**记谱上自相矛盾**（D 调号 + C 大调音高 → 满屏还原记号）。
- **触发面**：本机 4 个真实任务（`43de68cd1c7f`/`98dae2ae0b9c`/`ba5237c63c62`/`bf3409ba79ef`）**全部**给出 `F# min` → 这条路径**一次都没被走到过**。
- **修法二选一（产品语义取舍，没代拍）**：**A**（倾向）未知时按「记谱默认 = C」假定 → `nearest_transpose(0, target)`，**这正是旧代码的行为，旧代码的错在于“无条件”这么做，不是这个假设本身**；**B** 不动但把控件**禁用 + 说明原因**（对齐鼓轨 K 步进器的既有做法）。

## 第三轮：三连音三层齐补（用户指令「1.真支持得三层齐补」）

用户明确否掉「只补一层」—— 只补简谱层会让**五线谱有三连音、简谱没有**，正是前几轮一直在治的「两份谱对不上」。本轮把 ② 五线谱层 + ③ 简谱层补齐（① 检测层上一轮已写完），三层逐个端到端验收。

### ① 检测层（`app/services/tuplets.py`，新建）
- 判据**必须是对照实验**：`观察值 = 真实 onset 里连续命中的组数`；`对照值 = 同一批 onset 打乱相位但**保留每段 onset 个数**、重复 24 次取均值`；采信条件 `observed >= max(2, 3.0 × control)`。
- **保留密度这一步最容易写错**：连密度一起打乱 → 对照基线偏低 → 判据变松。
- 容差 `TOLERANCE_BEATS = 0.06` 拍（96 BPM ≈ ±37ms）：十六分在 1/4 处、距最近 1/3 正好 **1/12** 拍 → 容差**必须 < 1/12**，写成了断言防止被人调大。
- **相位固定 0、不扫**（全系统拍网格都从 t=0 按 BPM 切）。代价是漏（弱起/前奏），**漏 = 旧行为不破坏谱面，误报才破坏**。
- 终验矩阵 9 类素材：真实 4 轨 0 组不误报；合成八分 16 组采信、±0.05 采信、±0.09 拒绝；十六分三连音（1/6）与孤立 1 组**明确拒绝**（不是漏，是没做）。

### ② 五线谱层（`app/services/renderer.py`）—— 定点重建 + 修掉两个时间轴 bug
- **不能换网格**：全局 `(2,)` 会把 1/3、2/3 都吸到 0.5 并成和弦，信息那步就毁了、事后恢复不出来 → 只能拿**原始 onset 的音高**把这几拍重写。
- **不能逐小节量化**：`converter.parse(quantizePost=True)` 在 Part 层、建小节前执行，且 `chunkTolerance = ticksPerQuarter / max(divisors)` —— **同时发声容差取自 `max(divisors)`**；逐小节量化会让和弦从 95 个掉到 2 个 → 打断基线。这条路是死的。
- **bug A（主）**：Basic Pitch 写死 120 BPM tempo，music21 的 `quarterLength` 从 tick 算、与 tempo 无关 → `120/bpm` 倍系统误差；96 BPM 素材比值 1.25 → vocals **94 小节**里 19 节是凭空多的，修正后 **300.5 拍 / 76 小节**。修时间轴只能改 **tick**。
- **bug B（更隐蔽，本轮揪出）**：旧公式 `tick_new = tick_old × (bpm/120) × RES / tpb` 里的 `bpm/120` = **默认源就是 120 BPM**。写「自洽文件」测试（tempo=真实速度）立刻暴露：4 拍算成 3072 而非 3840 → 改为**先按源文件自身 tempo 还原真实秒**（逐条 `set_tempo` 生效）再换出去，对 120 BPM 源与旧式逐位一致。另补 `bpm ≤ 0 → ValueError`（`60/0` 会先抛 `ZeroDivisionError`）。
- **bug C（容器）**：48 音只落盘 39 —— 一组在原谱里**一个自己的音都没有**时回退 `container = part`，插入基准变 0 → 9 个音被塞到 Part 顶层、**脱离小节**、写 MusicXML 整批丢失。修 `_container_at`（按 offset 找小节）+ **两阶段「先删后插」**。
- **假阳性**：判「长音跨区间」用 `offset < start - 1e-6 < offset+dur`，上一组末音结束在 `0.9999999999999999` → 不等式成立 → 每组都触发"截断"刷 15 行日志 → 容差改加在**两侧**。
- **结论**：「跨小节 tuplet 写不出」**不成立**。修完容器 bug 后 `time-modification = actual-notes = 48`、`tuplet start` 16 组严丝合缝；且相位 0 时跨小节 tuplet 根本不可能出现（八分恒占 1 拍、四分恒占 2 拍起点偶数，4/4 里永不越线）。
