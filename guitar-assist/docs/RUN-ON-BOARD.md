# 上板运行说明（带屏版）

> 面向：把 guitar-assist 装到泰山派 RK3566 上，接 1.54" ST7789 彩屏 + 10 个按键 +
> ESP32 舵机机构，跑起来。
>
> 本文的接线数字**全部来自档3（《拨云》）的实机笔记**，不是推测：
> `48_接线总表_重接用.md`（10-10 用立创官方 40PIN 表逐项复核）、
> `29_触摸条硬件验收.md`（6/6 触摸键实机通过）、`key_test.py`、`lcd_check.py`。

---

## 一、三个可执行文件的分工

| 二进制 | 用途 | 需要什么 |
|---|---|---|
| `guitar_assist_ui` | **带屏主程序**（本轮新增）。屏 + 10 键 + 音频 + 机构，一个进程 | 屏、按键、（可选）声卡、舵机串口 |
| `guitar_assist` | 命令行版。调音/和弦识别往终端打印 | 只要串口终端，**不需要屏** |
| `mech_selftest` | 机构驱动自检。断言角度表 + 帧格式，可选真发一帧 | 无（带参数才碰串口） |

`guitar_assist_ui` 的调试顺序是**从外设往里**：先点屏 → 再按键 → 再机构。
不要一上来就跑完整界面，那样出问题时你分不清是哪一层。

## 二、接线表（照这张插）

### 2.1 彩屏：1.54" IPS / ST7789 / SPI / 240×240

| 屏脚（丝印） | 泰山派 40PIN | GPIO | 全局号 | 说明 |
|---|---|---|---|---|
| **DIN** (MOSI) | 脚 19 | GPIO4_C3 | — | SPI3_MOSI |
| **CLK** (SCLK) | 脚 23 | GPIO4_C2 | — | SPI3_CLK |
| **CS** | 脚 24 | GPIO4_C6 | — | SPI3_CS0（**硬件片选，代码不用管**） |
| **DC** | 脚 29 | GPIO3_B0 | **104** | 命令/数据选择（必须接） |
| **RES** | 脚 31 | GPIO3_C2 | **114** | 复位 |
| **BLK** | 脚 17 | — | — | 背光，接 3.3V 常亮（要调光才接 GPIO） |
| **VCC** | 脚 17 | — | — | **3.3V**。☠️ 接 5V（脚2/4）会烧屏 |
| **GND** | 脚 14 | — | — | |

> ⚠️ **`--dc` 是 104，不是 114。**
> 档3 早期的 `lcd_check.py` 里 `--dc` 默认值写的是 `114`，但那条注释把
> 「脚29」和「GPIO3_C2」混在一起了 —— GPIO3_C2(114) 其实是**脚31**，也就是 RES。
> 笔记 48 §2.5 已复核定稿：**DC(脚29)=104、RES(脚31)=114**。
> 若你的实物接法不同，用 `--dc/--rst` 覆盖，不用改代码。

### 2.2 右手 4 键（机械按键，一端接脚、一端接 GND）

| 键 | 40PIN | GPIO | 全局号 | `guitar_assist_ui` 参数 |
|---|---|---|---|---|
| UP | 脚 11 | GPIO3_A1 | 97 | `--up 97` |
| DN | 脚 13 | GPIO3_A3 | 99 | `--down 99` |
| SET | 脚 15 | GPIO3_A2 | 98 | `--set 98` |
| ESC | 脚 16 | GPIO3_A4 | 100 | `--ent 100` |

> ⚠️ **A3/A2 与脚号不单调**（脚13→A3、脚15→A2），照表填，别按顺序外推。
> 机械按键接 GND + 上拉 → **按下 = 低电平**（代码里 `active_low = 1`）。

### 2.3 左手 6 键（TTP223 触摸模块，一键直达和弦）

| 键 | 和弦 | 40PIN | GPIO | 全局号 |
|---|---|---|---|---|
| C1 | C | 脚 7 | GPIO1_A4 | 36 |
| C2 | G | 脚 12 | GPIO3_C4 | 116 |
| C3 | Am | 脚 18 | GPIO3_A5 | 101 |
| C4 | F | 脚 22 | GPIO3_A6 | 102 |
| C5 | **Dm** | 脚 26 | GPIO3_A7 | 103 |
| C6 | Em | 脚 32 | GPIO3_C5 | 117 |

对应参数：`--lk 36,116,101,102,103,117`

> ⚠️ TTP223 是**高电平有效**（按下=1），和机械按键**正好相反**。
> 代码里两套的 `active_low` 分别写死为 0 / 1，别混。
>
> ⚠️ 第 5 个键档3 丝印/验收是 **Dm**（不是 D）。`ui_demo.c` 的演示数据里写的是 D，
> 那是 PC 演示用的，以硬件为准。

### 2.4 机构与音频

| 项 | 值 | 说明 |
|---|---|---|
| 舵机串口 | `/dev/ttyS3` @ 921600 | 与档3 共用；用 `flock` 排他，被占则本程序放弃驱动（不乱写） |
| 音频采集 | 默认 `default`；档3 用 USB 声卡 `hw:1,0` | 档3 本体没有音频输入，调音需要另接拾音/麦克风 |

## 三、上板步骤

```bash
# ① PC 交叉编译
export SYSROOT=/path/to/tspi-sdk/sysroot
./scripts/build-rk3566.sh

# ② 传到板子
scp build-rk3566/{guitar_assist_ui,mech_selftest,dev_scan} root@<IP>:/root/guitar/

# ③ 板上：先离线自检机构（不碰硬件）
cd /root/guitar && ./mech_selftest
#    期望最后一行: 全部通过 (0 项失败)

# ④ 点屏（这一步过了 = SPI/DC/RES/接线全对）
./guitar_assist_ui --test-display
#    期望: 红 绿 蓝 白 黑 依次整屏

# ⑤ 跑完整界面
./guitar_assist_ui
#    期望: 演奏页(顶部 6 槽位 + 大写和弦名 + 指法图 + 底部状态)
#   · 左手 6 键 → 直接选和弦并驱动机构压弦
#   · Up/Down  → 上一个/下一个和弦
#   · Set      → 演奏页 <-> 调音页
#   · ENT      → 重新压弦
#   · 长按 Set → 设置(调亮度)
#   · Ctrl-C   → 退出（会先把舵机归位并断使能）

# ⑥ 第一次上板建议先"只看界面"（不碰舵机/声卡，排除干扰）
./guitar_assist_ui --no-mech --no-audio
```

## 四、屏不亮怎么判（照现象查，每次只改一个）

| 现象 | 原因 | 怎么试 |
|---|---|---|
| 全黑，**背光也不亮** | BLK / VCC / GND 没通 | BLK 直接接脚 17(3.3V)；量脚 17 是不是 3.3V |
| 背光亮，但整屏白/灰 | SPI 没通 / 初始化没到 | `ls /dev/spidev*` 看节点；确认设备树使能了 SPI3 + spidev；`--hz 12000000` 降速 |
| 花屏 / 雪花 | SPI 太快或线太长 | `--hz 12000000` 或 `--hz 10000000` |
| 颜色错乱 | ST7789 序列不匹配 | 先看屏背面丝印：`ST7789` 才对（NEVER 用 NV3030B 的序列） |
| 红蓝互换 | RGB/BGR 顺序 | 正常现象，改 `st7789.c` 的 `ST_MADCTL_DEFAULT`（0x00 ↔ 0x08） |
| 画面偏移 | 显存 offset | `--xoff/--yoff`（240×240 通常 0,0） |
| 黑白颠倒 | 反色设置 | 注释掉 `st7789.c` 里的 `ST_INVON` |

提前确认两件事：

```bash
ls /dev/spidev*          # 应该有 /dev/spidev3.0
gpioinfo | head -40      # 看脚29/31 是不是空闲（没被别的驱动占）
```

## 五、按键不灵怎么判

| 现象 | 原因 | 怎么试 |
|---|---|---|
| 右手 4 键**完全没反应** | sysfs GPIO 不可用 | 见下方"★ 上板必验"第 1 条 |
| 右手 4 键**按了没反应、松开才触发** | 极性反了 | 确认机械键是接 GND（低有效）。若你的键是接 3.3V，把 `ui_main.c` 的 `icfg.active_low` 改成 0 |
| 左手 6 键**一直触发/乱跳** | TTP223 半触发（手指接近未碰到） | 档3 笔记 29 记过这个现象。把 `ga_leftkey_cfg_t.debounce_ms` 从 20 加到 40~50 |
| 左手键**完全没反应** | 极性反了 | TTP223 是高有效；确认 `lcfg.active_low = 0` |
| 某个键一直不响应 | 杜邦线没插到底 | 档3 笔记 29 坑 2 就是这个：换插到底即可 |
| 启动就报"GPIO 打开失败" | 被别的驱动占用 | `gpioinfo` 查这个脚；`dmesg | grep -i pin` |

> ★ **上板必验**：
> 1. **`ls /sys/class/gpio/`** —— `input.c` 的按键走的是 **sysfs GPIO**。
>    泰山派 4.19/5.10 内核通常保留（deprecated 但可用），但若你的内核关掉了
>    `CONFIG_GPIO_SYSFS`，按键会**全部失效**（而屏还能亮，因为 `st7789.c` 走的是
>    gpiochip 字符设备，两套不共用）。真遇到这种情况，把 `input.c` 里
>    `gpio_open_line()/gpio_read_line()` 两个函数换成 gpiochip ioctl 即可，
>    其余逻辑不动（改动点已在该文件注释里标出）。
> 2. **`cat /sys/class/gpio/gpio97/value`**，按住 UP 键 —— 应从 `1` 变 `0`。
>    这一步能独立验证"接线 + 极性 + sysfs"三件事，比跑整个界面快得多。

## 六、这一轮顺带修掉的两个真机缺陷

两个都是"能编译、能在 PC 上演示、一上真机必挂"的类型：

### 6.1 按键极性双重反转

`gpio_open_line(gpio, active_low)` 会把极性交给内核（写 sysfs 的 `active_low` 文件），
而 `read_pressed()` 里**又**做了一次 `active_low ? (v == 0) : (v == 1)`。
内核翻转一次 + 代码翻转一次 = **双重反转** → 按下时读到"未按下"。

⇒ 现在 `gpio_open_line` **恒定传 0**（不交给内核），极性判断只留在用户态一处。
`scripts/check_ui_main.py` 里有回归断言盯着这一点。

### 6.2 UI 永远卡在"压弦中"

`mech_bridge.c` 的 `bridge_chord()` 里调了 `ui_set_mech_state(0, 1)`（"帧一发出就算就绪"），
但 `ui_app.c` 的 `fire_chord_changed()` 在**回调之后**紧接着调
`ui_set_mech_state(1, 0)`（"压弦中"）—— 后者覆盖前者，界面**永远显示"压弦中"**。

⇒ 职责重新划分：
- `ui_app` —— 选完和弦 → 置"压弦中"（意图）
- **主循环** —— 机构动作到位 → 置"就绪"（完成）
- `mech_bridge` —— 只转发命令，**不反向改 UI 状态**

由于 ESP32 目前不上报到位事件，"到位"暂由主循环按 `--settle`（默认 400ms）推进。
固件加上报后，改主循环那一段即可，UI 侧不用动。

## 七、参数速查

```
屏:    --spi <dev>   --hz <n>   --dc <gpio>   --rst <gpio>   --blk <gpio>
       --xoff <n>    --yoff <n>  --test-display
按键:  --up --down --set --ent <gpio>       --lk g0,g1,g2,g3,g4,g5
机构:  --mech <dev>  --baud <n>  --csv <file>   --no-mech
音频:  --audio <dev> --no-audio
其它:  --fps <n>     --settle <ms>  -v  -h
```

默认值就是第二节表格里的值，即：**不接任何参数就是档3 的接线**。

## 八、与档3 主程序共存（串口）

`/dev/ttyS3` 上档3 主程序（`guitar.service`）和本程序都想写。本层用
`flock(LOCK_EX | LOCK_NB)` 排他：

- 档3 的面板脚本（`servo_panel.py`，已加固）用同一把文件锁 → 互斥有效
- 本程序打开失败时**不静默乱写**，直接进离线模式（界面照常，舵机不动）

三种生产方式二选一：

| 方案 | 做法 |
|---|---|
| A. 分时 | `systemctl stop guitar` 后再跑 `guitar_assist_ui` |
| B. 分工 | 档3 管演奏曲目，本程序只在"和弦模式"用（各自错开串口） |
| C. 合并 | 把感知层（调音/识别）并进档3 主程序，直接由它承载 UI |
