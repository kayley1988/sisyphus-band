## 线程模型

**单线程 + 非线性分析**，刻意不用多线程：

- RK3566 是 4 核，但单核跑这个负载绰绰有余（每帧 < 5ms 计算）
- 单线程避免了音频线程和 UI 线程的数据竞争
- 板子上出问题时，串口日志是线性的，好排查

如果要加 GUI（LVGL），建议：采集+算法放一个线程，GUI 在主线程，
两者之间用一个**环形缓冲 + 双缓冲结果**通信，不要用锁。

## 关键参数及其来由

| 参数 | 值 | 为什么是这个值 |
|---|---|---|
| 采样率 | 44100 Hz | 吉他调音的事实标准，与乐器谐波关系直观 |
| YIN 分析窗 | 2048 帧 (46ms) | 低音 E 的 3.8 个周期。再短会测不准低音 |
| 色度图 FFT | 4096 点 | bin 宽 10.8Hz。2048 点太粗，8192 点延迟大 |
| 采集 period | 256 帧 | 端到端延迟目标 < 30ms |
| 色度图最低频率 | 140 Hz | 低于此分辨率不足，映射会出错 |
| 和弦平滑窗口 | 5 帧 | 3/5 多数表决，避免结果闪烁 |
| 和弦判定阈值 | 0.70 | 实测正确和弦 0.706~0.785，单音约 0.5~0.6 |
| 额外音证据门槛 | 0.12 | 真实和弦音占比 0.17~0.28，杂音 0.04~0.09 |
| 静音 RMS 门限 | 0.01 | 吉他正常演奏 0.05~0.3 |

## YIN 算法详解

### 为什么不能用简单自相关

自相关 `r(τ) = Σ x[j]·x[j+τ]` 在吉他上会八度误判。原因：

吉他的谐波幅度分布通常是 `基频 < 2次谐波`（这是弦振动和共鸣箱
共同作用的结果）。此时 `r(2T)` 可能比 `r(T)` 还大（T 是基频周期），
算法就取到了高八度。

### YIN 的三步修正

**步骤 1 — 差值函数**（而不是自相关）
```
d(τ) = Σ (x[j] - x[j+τ])²
```
用差值而不是乘积。这样"完全匹配"对应 d=0，比"乘积最大"更直观。

**步骤 2 — 累积均值归一化（CMNDF）** ← 关键
```
d'(τ) = d(τ) / [(1/τ) · Σ_{k=1..τ} d(k)]
```
除以累积均值。这一步抵消了"τ 越大、累积能量越大"的趋势，
使真正的周期点在 d' 上呈现为一个**低于阈值的凹坑**，
而倍频位置不会。

**步骤 3 — 绝对阈值 + 抛物线插值**
- 取第一个低于 0.12 的局部极小点（避免取到倍频）
- 用抛物线拟合 τ-1, τ, τ+1 三点，把整样本精度提到亚样本
- 没有这一步，高音弦误差能到 10+ 音分

### 置信度

直接用 `1 - d'(τ_est)`。周期性越强，d' 越小，置信度越高。
实测：真实吉他音 conf ≈ 0.98~1.00，白噪声 conf ≈ 0.36。
所以门限设 0.5 能干净地区分。

## 色度图详解

### 原理

把频谱的每个 bin 按频率折叠到 12 个半音类别：
```
频率 f → MIDI 小数 = 69 + 12·log₂(f/440) → 取整 → mod 12
```
这样 C2/C3/C4/C5 全部折叠到 "C" 维度。

**好处**：和弦的本质是音级组合（C-E-G = C 和弦），与八度无关。
弹 C 和弦无论在哪把位，色度图都是 C/E/G 三个峰。

**代价**：低音弦信息丢失（见下）。

### 频率分辨率问题（核心限制）

FFT 的频率分辨率 = `sr / N`。4096 点在 44.1kHz 下 = **10.8Hz**。

| 音符 | 频率 | 相邻半音间隔 |
|---|---|---|
| 6弦 E2 | 82.41 Hz | 4.9 Hz ← 小于一个 bin！ |
| 5弦 A2 | 110.0 Hz | 6.5 Hz ← 还是不够 |
| 4弦 D3 | 146.8 Hz | 8.7 Hz ← 勉强 |
| 3弦 G3 | 196.0 Hz | 11.6 Hz ← 够了 |

所以在 82Hz 处，你根本无法从 FFT bin 索引判断出这是 E 还是 F。
映射过去的 pitch class 是随机噪声。

**处理**：`MIN_FREQ = 140.0`，低于此的 bin 直接丢弃（`bin_to_pc = -1`）。
低音弦的信息由 YIN 单音检测补足。

**这个取舍的后果**：`Am`（A-C-E）和 `A`（A-C#-E）在色度图上
只差 C vs C#，而 A 弦的低音信息被丢弃时，两者很难区分。
实测中 Am 识别正确（0.785），说明靠三弦的 C 也能work，
但边界情况会更脆弱。

### 权重设计

`bin_weight` 在 140~1200Hz 之间为 1，超过 1200Hz 线性衰减到 0.05。

原因：吉他高次谐波会跨到相邻音级，制造"假的和弦音"。
抑制高频能提高纯净度。

## 和弦识别：模板匹配的改进

朴素做法：色度图与二值和弦模板做余弦相似度，取最大。

### 改进 1 — 根音加权

模板里根音权重 1.5，其他音 1.0。
真实演奏里根音通常最响，这能有效区分共享两个音的和弦对
（如 C=C-E-G 和 Am=A-C-E 共享 C、E）。

### 改进 2 — 多余音惩罚

计算不在模板里的音级能量占比，按比例降分：
```
score *= (1 - 0.5 · outside_ratio)
```
0.5 是权衡值：吉他泛音多，"多余音"天然不低，惩罚太狠会误伤正确和弦。

### 改进 3 — 包含关系裁决（最关键）

**问题**：`Cmaj7 ⊃ C`，且 `Am7 ⊃ Am`。扩展和弦因为"多余音更少"
反而得分更高，导致弹 C 报 Cmaj7。

**解决**：候选是扩展和弦时，检查"额外音"的能量：
```
if (chroma[extra_tone] < 0.12) score *= 0.90
```
若最终仍胜出，强制退回简单三和弦。

**效果**：识别率 5/11 → 11/11。

## 无障碍反馈编码设计

### 信息论视角

调音需要传递两个信息：**方向**（偏高/偏低）和**幅度**（差多少）。

| 通道 | 方向编码 | 幅度编码 |
|---|---|---|
| 提示音 | 高/低音高 | 节拍速率 |
| 振动 | 无法编码 | 脉冲长度 |
| 视觉 | 指针左右 | 指针偏移量 |
| 语音 | 文字 | 文字 |

**为什么振动不编码方向**：人对振动的"高低"感知很弱，
强行编码方向会增加认知负担。
振动的优势是**在嘈杂环境下依然有效**，所以专注于传达"还差多少"。

### 节流设计

| 反馈 | 最小间隔 | 原因 |
|---|---|---|
| 提示音 | 250ms | 4Hz，再快就成噪音 |
| 振动 | 500ms | 避免手麻 |
| 参考音 | 1500ms | 参考音长 1.2 秒，不能重叠 |
| 语音 | 800ms | 语音本身有长度，叠加会糊 |

节流是**必须的**：没有节流，每 93ms 一帧的提示音会连续不断，
用户根本没法听出节奏变化。

### 成功反馈的特殊处理

调准时播放**上升三音 C5-E5-G5**（523/659/784 Hz） + 双击振动。

选上升音阶而不是单一音：音乐心理学上，上升音阶天然表达
"完成/成功/正确"，下降音阶表达"失败"。这是跨文化的直觉。

## 扩展点

### 加 LVGL 界面

`main.c` 里的绘制部分（`draw_header`/`draw_cents`）换成 LVGL 调用。
算法层完全不用改，因为它只输出数据，不碰 UI。

建议布局：超大字号音名 + 全宽指针条 + 高对比配色（黑底黄字）。
颜色不要作为唯一区分手段（色盲用户）。

### 换语音方案

`feedback.c` 的 `speak_impl()` 是唯一入口。
推荐改成播放预录 wav：把 `ga_chord_def_t.voicing_name` 对应的文件
放好，用 ALSA 播。音质和亲和力都远好于 espeak-ng。

### 加节拍器 / 曲谱跟随

YIN 已经提供了实时音高流，可以在此基础上做：
- 音准实时评分（吹奏/演唱教学）
- 旋律提取（单音独奏转录）
